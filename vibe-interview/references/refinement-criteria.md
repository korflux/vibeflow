# Critérios de convergência (Fase 2)

Só as dimensões que importam neste pedido.

## 1. Valor para o usuário (prioritário)

| | Analgésico | Vitamina |
|---|---|---|
| Sinal | Dor aguda; workaround; pagariam; falam com emoção | "Legal"; aceno educado; hábito não muda |
| Ação | Priorizar | Só se trivial ou de graça no pacote |

3 pessoas *específicas* com o problema agora? O que fazem hoje no lugar? Frequência (diário > mensal)? Pull (pedem) ou push (você acha que deveriam)?

Red flags: "todo mundo poderia usar"; "tipo X, só melhor"; dor real mas rara.

## 2. Viabilidade

Tech central existe? Parte difícil = conhecida ou novel? Dependências que você não controla? Stack mínimo? Time-to-value em dias/semanas? Expertise ausente? Compliance?

Red flags: "só precisamos resolver [pesquisa hard] primeiro"; N dependências em cadeia; MVP ainda de meses.

## 3. Diferenciação

Não "melhor" — **diferente**, de um jeito que o usuário se importa.

Força decrescente: capacidade nova → 10× numa dimensão → novo público → novo contexto → UX bem mais simples → mais barato (fraco).

Red flags: só tech; "mais rápido/barato/bonito" sem razão estrutural; o diferenciador não é o que o usuário valoriza.

## Auditoria de assunções

| Tipo | Se errada… | Exemplo |
|---|---|---|
| Must be true | Mata a ideia — validar antes de buildar | "Vão compartilhar dados conosco" |
| Should be true | Muda GTM; o núcleo vive | "Preferem self-serve" |
| Might be true | Feature secundária | "Vão compartilhar com o time" |

## Matriz

|  | Alta viabilidade | Baixa viabilidade |
|---|---|---|
| Alto valor | Fazer primeiro | Vale o risco |
| Baixo valor | Só se trivial | Não fazer |

Diferenciação desempata no mesmo quadrante.

## Escopo de MVP

1. Um job, bem feito.
2. Assunção mais arriscada primeiro.
3. Time-box, não feature-list.
4. Not Doing obrigatório, com motivo.
5. Se não embaraça quem constrói, a v1 esperou demais.
