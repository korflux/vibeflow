# Lentes de expansão (Fase 2)

Uma lente que destravar. Não é checklist.

## SCAMPER

Reimaginar o que já existe. Fraco em greenfield puro.

| Letra | Pergunta |
|---|---|
| Substitute | Trocar componente, tech, público, modelo? |
| Combine | Fundir com outro produto/serviço? |
| Adapt | O que em outro domínio resolve o análogo? |
| Modify | 10× maior, 10× menor, mínimo absoluto? |
| Put to other uses | Quem mais usaria? Outro problema? |
| Eliminate | Sem essa feature? Zero config? Metade dos passos? |
| Reverse | Ordem oposta? Usuário faz o trabalho do sistema? |

## How Might We

`How might we [outcome] for [usuário] without [restrição-chave]?`

Bom: estreito o bastante para agir, amplo o bastante para criar, com tensão.
Ruim: "deixar usuários felizes"; "adicionar botão em settings"; solução embutida ("buildar um chatbot").
Vários HMW do mesmo problema desancoram a solução.

## Primeiros princípios

1. O que é verdade (não convenção)?
2. O que estamos assumindo?
3. Quais assunções são lei vs "sempre foi assim"?
4. Reconstruir só a partir das verdades.

Quando tudo parece "um pouco melhor que o status quo".

## Jobs to Be Done

Formato: *When I [situação], I want to [motivação], so I can [outcome].*

- Funcional: que tarefa completar?
- Emocional: como quer se sentir?
- Social: como quer ser percebido?

Concorrente real muitas vezes é o workaround.

## Ideação por restrição

1 dia. Uma feature. Sem a tech óbvia. Grátis. Usuário leigo. 10 pessoas vs 1 bilhão.

Corta ideia inchada ou vaga.

## Pre-mortem

12 meses no futuro; flopou. O que deu errado (tech, mercado, time, timing)? Prevenível? Quais falhas aceitamos?

Stress-test na convergência.

## Inspiração análoga

Similaridade estrutural, não de superfície. "Uber for X" é superfície. "Marketplace de dois lados que resolve confiança entre estranhos" é estrutura.
